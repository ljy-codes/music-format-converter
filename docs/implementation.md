# 实现方案与工程边界

版本 0.1.0，2026-10-08。用户原始需求和多方建议位于工作区外层，保持不变；本文记录实际实现，不把建议全文当作已落地功能。

## 1. 调用链

桌面 `MainWindow → WorkspaceViewModel → IConversionService → CoreConversionService → MusicConverter`。

导入提前增加只读列表阶段：三种入口（文件/文件夹/拖放）统一 await `AddInputs → ScanAsync → Task.Run(SourceScanner.Scan)`，无需输出目录或转换引擎。`Scanning` 状态可取消，锁定并发修改；关闭窗口等待扫描停止。候选文件清单与转换计划分离，修改模式/输出位置只使计划失效，不恢复成文件夹占位；显式预检仍重新扫描、排除输出树并探测内容。

命令行 `Program → CliArguments → MusicConverter`，复用同一套策略和报告，不另做一套转码规则。

核心链路：

1. `SourceScanner` 迭代扫描、去重、排除附件/链接/输出目录。
2. `AudioProbe` 调用 ffprobe 探测真实封装、编码、流、标签、封面；拒绝不适用文件。
3. `AudioPolicy` 生成 Copy / Remux / EncodeAlac / EncodeAac / EncodeMp3 / EncodeFlac / EncodeWav / Unsupported 计划，估算空间；需要 MP3 编码时检查本地 `libmp3lame` 能力。
4. 用户确认后 `MusicConverter` 再查源大小/时间/音频参数，防止使用过期计划。
5. `FfmpegAudio` 默认完整解码源音频，随后复制或转换到同目录唯一 `.part` 临时文件。
6. 探测输出，检查参数、完整解码、可靠声明样本数、PCM/复制哈希，再 `OutputFiles.Commit` 不覆盖提交。
7. 逐项返回 `ConversionResult`，用户可通过 `ReportWriter` 导出 JSON 和 UTF-8 BOM CSV。

不涉及数据库、SQL、缓存、Redis、MQ、网络服务或业务事务。文件的提交边界是单个输出文件；报告不是音频提交事务的一部分，导出失败不回滚成功音频。

## 2. 音质与格式决策

默认选择“满足兼容候选规则时尽可能不编码”，而不是“所有来源必须转同一个扩展名”。FLAC 不简单改名成 M4A，而是解码后转 ALAC；已兼容的 MP3 原样复制比再次有损压缩更合适。

ALAC 以实际编码能力为边界，主要处理最多 24 位整数无损来源；不会把 FFmpeg 的 `s32p` 缓冲格式误解为可以无损编码所有 32 位整数。无损浮点、DSD 和多声道首版保守拒绝。

有损来源解码为 24 位整数后编码 ALAC，不承诺浮点解码结果逐位不变，更不承诺恢复丢失音质。AAC 模式必须显式选择，不因节省空间静默替用户选择再次有损。

扩展模式以追加枚举值实现，原 Smart/Alac/Aac 及旧 PlanAction 数值保持不变。默认仍为 Smart（Apple Music），其策略不变。MP3 为显式 320 kbps，编码限定 32/44.1/48 kHz；FLAC/WAV 保留支持的整数精度及参数。有损源输出无损容器使用 24 位，不宣称提升音质。原生同格式优先 Copy。WAV 使用 RF64 auto 支持大文件，不映射封面视频流；标签/封面缺失沿用逐项警告。

编码容器不再固定 ipod：M4A 保留 faststart；MP3 使用 ID3v2.3 和 Xing；FLAC/WAV 使用各自 muxer。无损重编码统一连续时间戳、精度和 PCM 校验；MP3/AAC 以有损时长容差检查，不误套源精确样本计数。Windows 引擎含 LAME；当前原生 Mac 构建缺少 LAME 时仅新的 MP3 编码被预检拒绝，不影响已有 MP3 原样复制或其他输出模式。

只允许受控音频容器探测；不把播放列表、远程 URL、多音轨视频作为任意 FFmpeg 输入。普通文件名、中文、空格、下划线经参数数组传递，不进入 shell。

## 3. 异常和一致性

- 预检判定为 Unsupported（含无法识别）的项目不执行转换，以 Skipped 终态保留原因；处理阶段的源检查、解码、编码、权限或输出校验异常为 Failed。单项异常不阻止后续项。
- 磁盘满/输出盘消失属于批次环境故障，停止剩余项而非持续制造无效文件。
- 计划过期、源文件变化直接失败，必须重新预检；Windows 处理期间持有只读共享锁。
- 同名输出自动加编号，不覆盖；目录检查拒绝链接祖先；不清理源文件和不属于本次的临时文件。
- 子进程同时读取 stdout/stderr，限制捕获长度；探测 45 秒，长转换设置总超时和无进度超时。正常取消使用进程树终止并等待退出。
- 临时文件删除只操作当前任务的精确路径：首次失败后按 100/200/400/800 ms 重试，不使用已取消的转换令牌。持续占用/无权限时，将残留路径写入最终 ConversionResult.Message，UI 与 JSON/CSV 共用，取消结果不再声称“未保留临时结果”。

### 网络样本修复（2026-10-08）
- WMA Lossless 缺失位深时，仅明确的 `s16/s16p` 解码格式补为 16 位；已有位深优先，未知 `s32p` 不猜成 24 位，浮点及其他未知精度仍拒绝。
- AAC 与其他转码模式一样使用 `asetpts=N/SR/TB`，避免 ASF 时间戳间断导致 DTS 异常；对已接受的一/双声道明确 `mono/stereo` 布局，兼容 TAK 仅声明声道数量的文件。不改采样率或声道数，不降低校验要求。
- 不承诺对强制终止/断电自动恢复，也不保证网络文件系统的所有重命名、权限和时间戳行为与本地盘相同。
- Mac 不以操作系统名称假定卷大小写不敏感，路径采用 Ordinal，避免将 `A.flac` 与 `a.flac` 静默合并。尚未按卷/文件身份规范化大小写别名；大小写不敏感卷上手工输入不同大小写的嵌套输出路径可能漏掉排除。使用目录选择器的真实大小写，并将输出目录放在输入树外；此项列入 Mac 验收。

## 4. 校验的含义

默认源检查 + 转码输出检查，比仅检查退出码更严格。空 PCM 拒绝；WAV/AIFF PCM、FLAC、ALAC 在精确时基和可靠声明样本数可用时核对样本长度，避免完整帧边界截断仍被当作成功。

对无损来源转 ALAC 和 AAC 重封装，默认还比较统一 `pcm_s32le` 解码哈希；对复制比较文件 SHA256。AAC 再编码本就有损，改查参数/完整性和合理时长差。

这些检查不鉴定音质优劣、不识别所有伪无损、不证明历史文件未曾被截断，也不替代实际播放器导入。关闭源完整检查是明确降级选项，报告附带说明。

## 5. 界面与状态

ALAC 转码按解码采样数重建从零开始的连续时间戳（`asetpts=N/SR/TB`）。这避免 ASF/WMA 毫秒时间基舍入使 M4A 声明时长与真实采样数不一致而误判截断；不增加/丢弃采样、不重采样、不改变采样率或声道。原有两采样容差、空音频与截断拒绝及 PCM 核验保持不变；复制、重封装和 AAC 路径不受此修改影响。

中文深浅主题、虚拟队列、原生多选文件/目录、拖放、输出位置、策略预览、单项/总体进度、取消、失败重试、导出报告。

严格区分“导入 → 预检 → 用户开始转换”。输入或设置改变会废弃旧计划；执行期间锁定设置；关闭窗口先取消并等待任务退出。不存储用户路径到远端，不后台下载。

`ItemStatus.Skipped` 追加为值 5，原有 0～4 数值不变。预检 Unsupported 的终态为“已跳过”，优先于队列取消判定；执行批次发生异常时，UI 补齐结果也遵循同一规则。完成/失败/跳过/取消分别统计，跳过不参与失败重试。可执行计划意外缺少音频信息仍属 Failed，不以跳过掩盖内部错误。

报告 schemaVersion 仍为 1，增量加入 skipped 计数和 Skipped 状态字符串（JSON/CSV）。宽松消费者可继续读取；严格校验旧状态枚举的消费者必须更新。CLI 保持非全部处理退出 1：失败或跳过都返回 1，取消优先返回 130。

首版不持久化队列/主题，不支持断点续转，不自动写入 Apple Music 资料库。

## 6. 打包与平台

Windows 自包含 .NET + Avalonia + 锁定共享 FFmpeg 引擎，由 Inno Setup 生成当前用户安装包，同时生成便携 ZIP。Mac 必须分别在对应架构机器编译引擎和自包含程序，组装 app 并用 hdiutil 生成 DMG。

Mac 脚本与 CI 不是已完成 Mac 验收；签名/公证只提供显式可选入口。打包脚本不自动安装、推送或发布。公开验证摘要见 `verification.md`；含路径的详细证据仅保留在本地 `test.md`。公开源码 Release 不代表捆绑二进制已完成分发审核。
