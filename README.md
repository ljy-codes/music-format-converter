# 音乐格式转换器

离线批量整理本地音乐，以尽量保留音质的方式输出适合导入 Apple Music 的格式。中文桌面界面，支持文件/文件夹、多种音频格式、预检、进度、取消、失败重试与报告。

**当前版本：0.1.0 本地试用版。** Windows x64 为本次本机构建目标；macOS Intel / Apple Silicon 提供原生构建与 DMG 脚本，尚未实机验收。Apple Music 的实际导入和播放也仍需用户设备验证，不能把编码成功等同于播放器兼容认证。

## 快速使用

1. 安装 Windows 安装包，或解压便携包后运行 `MusicFormatConverter.App.exe`。不要只单独复制 EXE，旁边的 `tools` 和运行库必须保留。
2. 点击“添加文件”或“添加文件夹”，也可以拖入文件/目录。导入后立即后台扫描并显示候选歌曲，不必先选输出目录；扫描可取消，不会自动转换。
3. 选择一个与源目录分开的输出目录，默认选择“Apple Music · 智能保真”。有其他用途时才选择 ALAC/AAC/MP3/FLAC/WAV。
4. 点击“预检”，检查每项拟采用的策略、不支持原因和空间估算；此时不生成音频。
5. 点击“开始转换”。单个文件失败不影响其他文件；磁盘耗尽或输出盘丢失会安全停止余下任务。
6. 检查结果，可导出 JSON / CSV 报告，再自行将成功输出导入播放器。

运行不需要联网、系统 FFmpeg 或另装 .NET。首次开发构建需要下载工具和依赖，与成品离线运行不同。

## 音质策略

| 模式/来源 | 处理 |
|---|---|
| 智能保真：已识别为兼容候选的 MP3、AAC/ALAC M4A、整数 WAV/AIFF | 原样复制，避免重复编码；仍默认完整解码检查 |
| 智能保真：其他封装中的 AAC | 优先无重编码重封装为 M4A |
| 智能保真：FLAC、APE、WavPack 等可解码无损音频 | 转 ALAC / M4A，保留采样率、声道和有效位深 |
| 智能保真：Opus、Vorbis、WMA 等其他可解码有损音频 | 转 ALAC / M4A，避免再次有损编码；**不会恢复丢失音质，文件可能增大** |
| 统一 ALAC | 显式选择所有适用来源转 ALAC，已有 ALAC 可复制 |
| AAC 256 kbps | 显式选择有损压缩；已有 AAC 优先复制/重封装，不为“统一码率”重复编码 |
| 自选 MP3 320 kbps | 显式选择有损编码；已有原生 MP3 原样复制，不强制改为 320 kbps |
| 自选 FLAC | 无损归档，保留支持的整数精度；已有 FLAC 原样复制，不按 Apple Music 兼容规则选择格式 |
| 自选 WAV | PCM 音频，体积较大；已有支持的整数 PCM WAV 原样复制；转码不嵌封面，部分标签可能无法保留 |

不是改扩展名。以实际容器和编码探测结果决定策略；文件名中的 `_` 不代表新的格式，正常保留。并非所有扩展名、所有规格、所有历史编码变体都已验证。

### 首版边界

- 主要支持单声道/立体声、最高 24 位整数无损来源、受支持的标准采样率最高 192 kHz；AAC 编码不接受高于 96 kHz 的来源。不会偷偷降采样或下混。
- MP3 320 kbps 编码仅支持 32/44.1/48 kHz，其他采样率明确拒绝，不自动降采样。需要离线引擎内置 `libmp3lame`；当前 Windows 包具备，原生 Mac 构建脚本未编入该编码器，会在预检提示不支持新增 MP3 编码（已有 MP3 复制不受影响）。
- 有损音频转 ALAC/FLAC/WAV 不会恢复音质，体积可能增大。候选列表中的后缀只是提示，是否可转换仍在预检按实际内容判断。
- 32 位整数、浮点无损来源、DSD、多声道、加密/受保护文件等不支持时明确提示；不提供解密或 DRM 绕过。
- CUE 只提示，不分轨；整轨音频仍单独处理。不保证外置歌词、内嵌歌词、自定义标签或多张封面完整迁移。
- 转码尽量保留常见标签及第一张内嵌封面；发现标签缺失时给出警告。原样复制始终保留原有字节，即使关闭转码元数据选项。
- 默认独立检查源音频并校验转码输出；关闭源检查会降低发现损坏文件的能力。不声称能发现一切历史截断或音质缺陷。
- 不自动导入/修改播放器资料库，不改写或删除源文件，不做升频“增强”。
- Mac 按大小写区分输入路径，避免在区分大小写的卷上漏掉不同音源。请通过选择器使用真实目录大小写，并将输出放在输入树外；同一文件的大小写别名未按文件身份合并。

## 安全与报告

- 无 shell 拼接命令；音频子进程只允许本地文件/管道协议，限制格式探测、输出日志和执行时间。
- 排除输出目录和链接，避免递归重复；文件同名时自动编号，绝不覆盖已有输出。
- 先写同目录唯一临时文件，校验通过后才提交正式文件；复制核对 SHA256，无损转换默认核对解码 PCM。
- 正常取消/关闭窗口会等待子进程回收，仅清理本次拥有的临时文件；遇到占用会在约 1.5 秒内有界重试，仍失败则在最终结果及报告提示残留路径，不误报已清理。断电/强制杀死整个应用可能留下 `.mfc-*.part`。
- 报告包含本地完整路径和错误摘要，只在用户选择的位置落盘，不上传。CSV 对公式前缀作防护。
- 预检判定不支持或无法识别、未执行转换的项目显示“已跳过”，保留原因并单独统计，不计入失败或“重试失败项”。实际处理中的源检查、解码、编码或输出校验异常仍为“失败”。
- JSON 报告保持 `schemaVersion: 1`，新增 `skipped` 计数及 `Skipped` 状态；CSV 同样使用 `Skipped`。严格枚举状态的外部脚本需要补充该状态。

## 开发与验证

需要 .NET SDK `10.0.400`。Windows 开发引擎准备：

```powershell
pwsh -NoProfile -File ./scripts/fetch-engine.ps1
dotnet test ./MusicFormatConverter.sln -c Release
dotnet run --project ./src/MusicFormatConverter.App -c Release
```

开发引擎放在 `tools/<RID>/`，安装版放在程序同级 `tools/`，也可用 `MFC_ENGINE_DIR` 指定。缺少引擎会明确报错；部分集成测试将标记跳过，**有跳过不等于完整验收**。

命令行与界面共享同一转换核心：

```powershell
dotnet run --project ./src/MusicFormatConverter.Cli -- preview --output "D:\音乐输出" "D:\音乐源"
dotnet run --project ./src/MusicFormatConverter.Cli -- convert --output "D:\音乐输出" --mode smart --report "D:\音乐报告" "D:\音乐源"
# 可选其他输出格式，默认仍为 smart
dotnet run --project ./src/MusicFormatConverter.Cli -- convert --output "D:\FLAC归档" --mode flac "D:\音乐源"
```

`preview` 不写音频；`convert` 会执行真实转换。CLI 的 `--flat`、`--skip-source-check`、`--strip-metadata` 分别控制平铺、关闭独立源检查、关闭转码标签保留。转换退出码：0 全部成功、1 未全部处理（含失败或跳过）、2 全局错误、130 取消。退出码 1 不代表每个未处理项都转换失败，应结合逐项状态判断。

## 工程结构与交付

- `src/MusicFormatConverter.Core`：探测、策略、批量转换、验证、报告。
- `src/MusicFormatConverter.App`：Avalonia 中文桌面界面。
- `src/MusicFormatConverter.Cli`：离线脚本入口。
- `tests`：策略、路径安全、真实音频集成、CLI、UI 状态与无头渲染测试。
- `docs/implementation.md`：实现决策、处理链及兼容性边界。
- `docs/verification.md`：去除本地路径的公开验证摘要；详细验收记录保留在本地 `docs/test.md`，不提交。
- `docs/packaging.md`：Windows 安装包、macOS 原生 app/DMG、手动 CI。
- `docs/engine-provenance.md`：引擎锁定版本、校验和、源码与再分发待办。

源码和构建脚本可供审阅；二进制、引擎、缓存、测试产物不提交 Git。工作流只在手动触发时构建，不自动发布 Release。当前二进制未代码签名；**Windows 引擎第三方依赖的完整源码/许可分发审核未完成，不作为可直接公开发布的正式版**。
